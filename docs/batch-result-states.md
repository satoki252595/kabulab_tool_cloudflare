# バッチ結果と空欄の扱い

取得・保存の失敗と、原本に裏付けられたゼロ・不該当を区別する。分類・計算・集計は通常の機械処理で行い、LLMや全市場の再取得を追加しない。

| 結果 | 必要な根拠・処理 |
|---|---|
| 数値0 | 原本の明示値。欠測へ変換しない。日証金の融資残高0・貸株残高正なら貸借倍率0、分母0や値なしなら算出不能 |
| 原本明示不該当 | 原本・主体・期間・全文根拠の一致。保有明細は専用状態と別件数にし、明細公開件数・価格照合完了には加えない。旧要確認markerは通常再開時に最大1通だけ再資格する |
| 観測時点の正常0件 | 一覧の取得・原本保管・構造検証・対象選択まで完了。処理未着手や通信失敗と分ける。提出日全体の確定や最新期の充足は意味しない |
| 公表待ち・公表遅延 | CFTCは予定期間・基準日・公表予定日・観測最新日を記録し、通常障害とは別集計。原本を保管しても予定期の観測値は0件のまま、全取得元の完了確認は通さない |
| 原本未提供 | Yahoo日足のNULL・対象日不在は`source_unavailable`。売買不成立か配信欠測かは未確定。出来高0・前日終値・取得成功へ変換せず、同runで再取得しない。旧保管物の`genuine_source_gap`は当時の分類名で、原因の確定証拠ではない |
| 算出不能 | 履歴本数不足、分母0、金額換算の根拠不足等。MA・出来高倍率・優待利回りの空欄を別値で埋めない |
| 判定保留 | マクロは必要入力がなく結論が確定しない場合にHOLD。取得済み入力だけで条件不成立や見送りが確定する場合は、その判定を維持 |
| 通信・解析・保存失敗 | HTTP失敗、想定外構造、主体・期間不一致など。正常0件・不該当へ変換しない |
| 保存結果不明 | 未完記録を維持し、後続・自動再送を停止。別の正常取得で過去の不明結果を解除しない |

5分足は既存の`source_empty`・`source_available`・`source_unavailable`と原本SHA・受領時計・最終採用日を維持する。全NULLだけで売買なしとは認定しない。日足の診断は出来高の`0`・`null`・項目欠測`missing`を別表示する。

有報39項目・財務・タグも、原本なし、原本内の項目欠落、明示不該当、対象外の期、未同期、未判定を分ける。タグ候補なし・全候補不採用は保存済み判定に基づく結果で、空タグだけを再判定対象にしない。保存媒体に項目がないことだけで公式未開示とは断定しない。

通常のCF/ActionsとSSHの有限補完は同じ共有処理を使う。定期時刻・起動資格・データ有効期限は[時刻契約](stock-scheduler.md#取得処理の時刻契約)、全機能は[一覧](batch-data-inventory.md)を参照。
