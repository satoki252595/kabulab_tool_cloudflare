# 事業タグ資金フローマップ（全タグマップ）実装手順書

銘柄ごとの「事業タグ」と週次の売買代金から、投資家が
「どの事業分野にお金が集まっていて、流れがどう変わったか」を一望できる
静的 HTML レポートを作るための手順書。

- 本書の前提は **WEB 公開**。使うデータは公開可能なものだけに限定して設計する
  （第1章）。本リポジトリ内の参照実装（`TOOL/` 配下）は個人利用前提の
  非公開版であり、入力データの置き換えが必要な箇所はその都度明記する。
- 数値はすべてスクリプトの機械集計で作る。文章は固定文とし、実行時に
  LLM へ数値や解説を作らせない（再実行で同じ入力から同じ出力が得られる
  決定的生成が絶対条件）。
- 参照実装: `TOOL/mf-dump-divisions.mts`（区分表の出力）、
  `TOOL/mf-biztag-precompute.py`（週次集計）、
  `TOOL/mf-biztag-report.mts`（HTML 生成）。再生成手順は `TOOL/README.md`。

## このレポートが答える問い

1. 今、どの事業分野（タグ）に売買代金が集まっているか（絶対規模）。
2. ここ数週で、お金の行き先はどう変わったか（シェアの変化と買い優勢度）。
3. その数字はどこまで信用できるか（対象範囲・カバレッジ・前提の限界）。

画面設計（第4章）はこの順番で読めるように組む。「誰が買ったか」
（投資部門別の買い越し）は測っていない。二次市場では買い手と売り手が
同額で存在するため、業種・タグ単位の「純流入額」は原理的に存在しない。
本レポートの「お金の流れ」は **売買代金のシェアと、上昇日に付いた
売買代金の割合（買い比率）** で代用表現する。この定義を画面上に明記する。

## 全体構成

```
[一次データ]            [タグ付け]              [集計]                 [生成・公開]
有報テキスト      →  単語帳の語で候補抽出  →  週次集計スクリプト  →  静的 HTML 生成  →  静的ホスティング
日足(終値・出来高)     自社事業性の判定        中間 JSON を出力         (固定文+機械集計)
単語帳(語+区分)        銘柄→タグ(複数可)       監査指標も同時出力
```

- 集計と HTML 生成を分離し、間に中間 JSON を置く。表示の試行錯誤は
  生成側だけで完結し、集計を再実行せずに済む。
- 全工程を読み取り専用クエリ＋ローカルファイル出力で構成すると、
  本番 DB を汚さずに何度でも再生成できる。

## 1. データ前提（公開可能なものだけを使う）

### 必要なデータ

| データ | 内容 | 粒度 |
|---|---|---|
| 銘柄マスタ | 銘柄コード、名称、市場区分など | 銘柄 |
| 日足 | 終値、出来高（売買代金 = 終値 × 出来高） | 銘柄 × 日 |
| 事業タグ | 銘柄 → タグ（複数可）、判定状態 | 銘柄 |
| 単語帳 | タグの一覧と区分（川上 / 川下 / 流通） | タグ |

### 公開可否の線引き

| 対象 | 扱い |
|---|---|
| 事業タグ・単語帳 | 自前の成果物として公開できる。ただし判定根拠として保存した開示文書の原文抜粋は転載しない（タグ名・件数・集計値のみ出す） |
| 株価・出来高 | 再配信の許諾があるデータだけを使う。個人利用プランの相場 API（例: J-Quants の個人向けプラン）は公開 Web への配信が規約違反になるものがあるため、採用前に規約で「公開配信可」を必ず確認する |
| 取引所の無償配布データ（業種分類・統計類） | 個人利用前提のものが多い。公開版では使わない前提で設計し、使う場合は許諾を確認してからに限る |
| 派生集計値（シェア・指数・比率） | 生データを出さず集計値だけを公開する設計でも、原データ側のライセンス確認は免除されない。項目ごとに根拠を記録する（第6章） |

参照実装（非公開版）の入力は「Notion の事業タグ × 自社 D1 日足 ×
単語帳台帳」。公開版では日足の取得元を配信許諾のあるものへ差し替える
ことが最大の変更点になる。タグと単語帳は自前成果物なのでそのまま使える。

## 2. タグ体系の作り方

### 粒度

- 「事業・製品の単位」とする。東証33業種より細かく、個別製品（型番）
  より粗い中間層。参照実装では単語帳 212 語（v5）で運用している。
- 各語に区分を持たせる: 川上（素材・部品・装置）/ 川下（製品・
  サービス）/ 流通・サービス。区分の正本は単語帳側の属性であり、
  保存先の列で表現しない（銘柄側は1列のタグ集合として持つ）。

### 単語帳の選定基準

- 語の出典を公的資料に限定する（日本標準産業分類、経済安全保障の
  特定重要物資、日本成長戦略、METI の産業戦略など）。出典の無い語は
  登録しない。
- 単語帳は版管理し、レポートには版（例: v5）を明記する。

### 銘柄への付与ルール

1. 有報の「事業の内容」等にキーワードが実際に現れた語だけを候補にする
   （現れなかった事業には付かない。これが「漏れ」の主因であり、隠さず
   開示する）。
2. 候補ごとに「その会社自身が今その事業を営んでいるか」を判定し、
   根拠文と一緒に保存する。
3. 判定状態（判定済 / 未判定）を銘柄ごとに持ち、集計対象は判定済のみ。

### MECE ではないことを前提に設計する

- 重なり: 1 銘柄に複数タグが付く。概念同士も重なる。「その他」の
  受け皿は無い。
- 集計では複数タグ銘柄の売買代金を各タグへ重複計上する（タグ単位の
  コホート指標として扱う）。そのためタグ合計は実売買代金より大きく
  なる（参照実装の実測で 2.584 倍）。重複倍率を必ず表示する。
- 未使用の語（単語帳にあるが1社も付かなかった語）と、判定済みだが
  タグ無しの銘柄数を開示する。「何が選ばれていないか」を読者が
  判断できることが信頼性表示の核になる。

## 3. 集計仕様

### 週次化と売買代金の上下分け

- 週は月曜起点の ISO 週（例: `2026-W44`）。
- 銘柄×日の売買代金 = 終値 × 出来高。
- 前営業日の終値より上なら「上昇日の売買代金（up）」、下なら
  「下落日の売買代金（down）」。同値はどちらにも入れない。
  前日比較のため、集計開始日の7日前から日足を読む。
- 銘柄×週に合計した後、銘柄の全タグへ同じ金額を配る（重複計上）。

### 指標の定義

| 指標 | 定義 | 読み方 |
|---|---|---|
| 買い比率 | up ÷ (up + down) | 50% が中立。実際の買い越しではない |
| シェア | そのタグの週売買代金 ÷ 全タグ合計（重複計上ベース） | 市場全体に対するシェアではない |
| シェア指数 | 週シェア ÷ 基準シェア × 100。基準は開始4週の平均。開始4週が 0.05% 未満の極小タグは期間中央値を基準にする（床を置かないと指数が暴れる） | 100 が開始時点並み |
| 資金の出入り | 直近4週のシェア − その前4週のシェア（百分率ポイント）。3銘柄以上のタグだけ対象 | プラス = 相対的に流入 |
| 順位 | 週ごとの全タグ中シェア順位 | バンプチャート用 |

### 区分集計

川上 / 川下 / 流通ごとに、所属タグの up・down・合計を単純合計する
（重複計上ベースで統一）。区分シェアの分母も全タグ合計を使う。

### 監査指標（集計と同時に出力する）

画面の「前提と検証」節のため、次を必ず算出する。

- 判定済み銘柄数、タグ付き銘柄数と割合、判定済み無タグ銘柄数
- 単語帳の語数、実際に付いた語数、未使用語の一覧（区分つき）
- 1銘柄あたりタグ数の平均・中央値・最大と分布（1〜5個、6個以上）
- 売買代金カバレッジ = タグ付き銘柄の売買代金（重複なし）÷ 市場全体
- 重複倍率 = 全タグ合計（重複計上）÷ タグ付き銘柄の売買代金（重複なし）
- 集中度 = 上位10タグのシェア合計、累計50%に達するタグ数
- 共起の多いタグペア上位10（重なりの実例表示用）

### データ品質ゲート

- 日足の同期が揃っていない週は表示対象から外す。目安は「上下分類
  できる売買代金が全体の 99% を超える週」から開始する（参照実装では
  実測で開始週を決めた。理由を開始週の注記として画面に残す）。
- 期間合計の売買代金が 0 のタグは行を作らない。
- 区分が引けないタグ（単語帳に無いタグ名）があれば警告を出す。
  黙って落とさない。

### 中間 JSON のスキーマ

集計スクリプトの出力は次の形を基本とする（参照実装の
`mf-biztag-heatmap.json` と同形）。

```jsonc
{
  "periods": ["2026-W27", "..."],          // 週ラベル
  "from": "2026-06-29", "to": "2026-10-30",
  "meta": { "judged_rows": 3692, "tagged_stocks": 2949, "vocab_version": "v5", "...": "..." },
  "rows": [                                  // タグごと（期間売買代金降順）
    { "tag": "...", "stocks": 42, "division": "upstream|downstream|distribution",
      "turnover_total": 123456789,
      "cells": [0.5123, null],               // 買い比率（週ごと）
      "share_cells": [0.02345, null],        // シェア（週ごと）
      "turnover_cells": [123456] }           // 週売買代金
  ],
  "divisions": [ /* 区分ごと: label, stocks, tags, cells, share_cells */ ],
  "flow": { "recent": ["..."], "prev": ["..."], "inflow": ["..."], "outflow": ["..."] },
  "audit": { /* 上記監査指標 */ }
}
```

欠損は `null` で表し、表示側で「データなし」として扱う。0 で埋めない
（欠損と実測ゼロの混同を防ぐため、集計側の内部計算を除く）。

## 4. 画面設計（投資家向けの見やすさ）

### 読む順序

上から順に「結論 → 根拠の前提 → 詳細」へ掘り下げられる構成にする。

1. 要約: KPI 4点（売買代金カバレッジ、タグ付き銘柄数、付いた語数 /
   単語帳の語数、重複倍率）＋要点3行（区分シェアの開始→直近、
   流入・流出トップ、MECE でない旨）。
2. 全タグマップ（主役の図。第4章「主役の2図」）。
3. 川上・川下・流通: 区分シェアの推移と買い比率。
4. 資金の出入りランキング: 直近4週 vs 前4週。
5. 順位の推移: 上位タグのバンプチャート。
6. 前提と検証: 監査指標の一覧（粒度、選定・未選定、カバレッジ）。
7. 全タグ一覧表: 検索・絞り込み・並び替え付き。数値の正本はここ。
8. 方法・注意・出典: 指標定義、免責、生成情報。

### 主役の2図

200を超えるタグを投資家が直感的に読むには、ヒートマップ単体では
絶対規模が伝わらない。次の2図を主役にする（可視化手法の調査結論）。

#### ツリーマップ（全体像）

- 面積 = 期間売買代金、色 = 買い比率（50%中心）またはシェア指数
  （100中心）の切替式。川上 / 川下 / 流通でグルーピングする。
- 「どこが大きくて、どこが熱いか」が一目で分かることが目的。
  Finviz のマーケットマップと同じ読み方に寄せる。
- 小さなタグはラベルを省略し、ホバー / タップでタグ名・売買代金・
  シェア・指数を表示する。モバイル幅では一覧表への導線を併記する
  （小さい矩形のタップ精度に依存しない）。

#### 四象限図（変化の読み取り）

- 横軸 = シェア水準（直近4週の平均シェア、対数軸）、
  縦軸 = シェア変化率（直近4週 ÷ 前4週）。点がタグ、点の大きさは
  銘柄数、色は区分。
- 右上が「大きく、増えている」。左上の小さい急増は指数の床問題と
  セットで注記する。
- 余裕があれば直近数週の軌跡を線で結ぶ（相対回転グラフ式）。
  ただし全点に軌跡を付けると読めないため、選択中タグだけに付ける。

### 補助の図

- 区分シェア: 100% 積み上げ面グラフ（3区分のみ。重心の移動を見る）。
- バンプチャート: シェア上位 12 タグの週次順位。交差が主役の交代を示す。
- ヒートマップ（シェア指数 / 買い比率）: 詳細確認用に降格する。
  色は「変化」専用とし、絶対値はツールチップと一覧表で読ませる。

### やらないこと

- Sankey 図: タグ間に保存則が無く重複計上のため、「AからBへ流れた」
  という誤解を生む。
- ストリームグラフ: 形は印象的だが値が読めない。
- 絶対シェアを色の濃淡で表すこと: 分布が歪んで大半のタグが同色に
  潰れる。絶対規模は面積（ツリーマップ）と表の数値で表す。

### 色と数値のルール

- 発散色は中心値を明示する（指数は 100、買い比率は 50%）。
  シェア指数は log2 スケールで ± を対称にする。
- 色覚多様性に配慮し、色だけに意味を持たせない（数値・順位を併記）。
- 欠損セルはグレーで「データなし」とツールチップに書く。
- 金額は兆円 / 億円表記に丸め、正確な値はツールチップと表に置く。
- 装飾は最小限にする。グラデーション見出し、発光シャドウ、
  意味のないアニメーション、絵文字アイコンは使わない。数字の
  フォントは等幅にし、見出し階層で読む順序を作る。

### 初心者向けの説明

- 専門用語（買い比率、シェア指数、川上 / 川下など）には初出で
  バルーンヘルプ（短い平易な説明）を付ける。
- 誤解防止文を図の直下に固定する。必須の3点:
  「買い比率は実際の買い越しではない」
  「シェアの分母は市場全体ではなくタグ合計（重複計上）」
  「タグは公式分類ではなく、漏れと重なりがある」。
- ページ冒頭に「投資助言ではない」旨と、データの時点・単語帳の版・
  生成日時を明記する。

### 操作

- 一覧表: 区分ボタンでの絞り込み、タグ名検索、列クリックでの
  並び替え、表示件数の表示。
- 図と表の相互リンク（図で選んだタグを表でハイライトする等）は
  任意。付けない場合も、表が単独で全情報を担うこと。

## 5. 実装手順

1. **単語帳を用意する。** 語・区分・出典を1つの正本にまとめ、版を
   付ける。以後の集計はこの版に固定し、JSON と画面に版を出す。
2. **タグ付けパイプラインを作る。** 開示文からの候補抽出 → 自社事業性
   の判定 → 根拠と状態の保存。判定に LLM を使う場合も、入力（根拠文）
   と出力を保存し、再判定の範囲を管理できる構造にする。
3. **区分表を出力する。** 単語帳から「タグ名 → 区分」の JSON を出す
   小さな読み取り専用スクリプト（参照: `mf-dump-divisions.mts`）。
4. **週次集計スクリプトを作る。** タグ × 日足から第3章の中間 JSON を
   出す。読み取りのみで完結させ、対象期間を開始・終了日で明示する
   （参照: `mf-biztag-precompute.py`）。
5. **HTML 生成スクリプトを作る。** 中間 JSON → 単一の静的 HTML。
   文章は固定文、数値は機械集計のみ（参照: `mf-biztag-report.mts`）。
   主役の2図（ツリーマップ・四象限）から実装し、補助図と表を足す。
6. **検証する。** 第6章のチェックリストを通す。とくに生成物の
   スクリーンショットを実際に開いて、潰れ・切れ・色の意味を確認する。
7. **公開する。** 静的ホスティングへ配置。生成日時・対象期間・
   単語帳の版・免責が画面に出ていることを公開条件とする。

技術選定は自由だが、図表は SVG か Canvas のどちらかで完結させ、
外部 CDN 依存を避けると再現性と保守が楽になる（参照実装は外部依存
なしのインライン SVG + 最小限の JS）。

## 6. 検収チェックリスト

### 数値

- [ ] 任意の1タグ×1週を原データから手計算し、集計値と一致する。
- [ ] 週シェアの全タグ合計が 100% になる（重複計上ベース）。
- [ ] カバレッジ・重複倍率が監査指標どうしで整合する。
- [ ] 同じ入力で再実行すると同じ HTML が出る（生成日時を除く）。
- [ ] 欠損週・売買代金 0 のタグが黙って消えていない。

### 表示

- [ ] 実物のスクリーンショットで、ツリーマップの面積順と一覧表の
      売買代金順が一致して見える。
- [ ] 色の凡例と中心値（100 / 50%）が図の近くにある。
- [ ] モバイル幅でも表が読み取れ、図の操作不能箇所に依存していない。
- [ ] 一覧表の検索・絞り込み・並び替えが実際に動く。
- [ ] 専門用語の初出に説明があり、誤解防止文が図の直下にある。

### ライセンスと公開

- [ ] 画面に出る全データ項目について、公開根拠（契約・規約の確認先）
      をプロジェクト内に記録した。
- [ ] 開示文書の原文抜粋が画面・JSON に含まれていない。
- [ ] 「投資助言ではない」旨、データ時点、出典が明記されている。

## 7. 運用

- 更新は週次が基本（週末に前週分までを再生成）。
- 単語帳の版を上げたら、影響銘柄の再判定と全期間の再集計を行う。
  版が混ざった集計はしない。
- タグは判定時点の事業内容に基づく。画面に「タグの時点」を出し、
  期間途中の事業変化は反映されない旨を注記する。
- 日足の欠けや同期遅延で品質ゲート（第3章）を満たさない週は、
  無理に埋めず表示対象から外し、理由を注記する。

## 付録: 用語集

| 用語 | 意味 |
|---|---|
| 事業タグ | 銘柄が営む事業を表すラベル。1銘柄に複数付く |
| 単語帳 | タグの語彙一覧。各語に出典と区分を持つ |
| 区分 | 川上（素材・部品・装置）/ 川下（製品・サービス）/ 流通・サービスの別。単語帳側の属性 |
| 買い比率 | 上昇日の売買代金 ÷（上昇日＋下落日）。買い越しそのものではない |
| シェア | 全タグ合計（重複計上）に対する割合。市場シェアではない |
| シェア指数 | 開始4週の平均シェアを 100 とした相対値 |
| 重複計上 | 複数タグを持つ銘柄の売買代金を各タグへ重ねて数えること |
| カバレッジ | タグ付き銘柄の売買代金が市場全体に占める割合（重複なし） |
