## 保存入力で確認した候補漏れ

cand-v1のタグposting cap60は対象タグの母集団が61社以上になるとそのタグの寄与を丸ごと除外する。今回のcorpus3689社では、141Aの「食品小売」が69社なので、イオン8267/ライフ8194との唯一の共有タグが消える。「ペット関連」31社を共有するイオン九州2653/バロー9956は残る。145AのSaaS216社/生成AI75社は除外され、サイバーセキュリティ58社は残る。そのためセキュリティ/SIへ偏り、corpusに存在するkubell4448/ヌーラボ5033が候補50に入らない。

## 単発wrapperの操作

新規依存はなく、既存Nix環境のNode/pnpmと既存`.env`だけを使う。原文を含む引数ファイルと保存先はGit対象外のprivateディレクトリに置く。

```bash

pnpm exec tsx --env-file-if-exists=.env services/yuho-quant/data-scripts/recover-unjudged-competitors.ts generate <private-dir> 5
pnpm exec tsx --env-file-if-exists=.env services/yuho-quant/data-scripts/recover-unjudged-competitors.ts generate <private-dir> 83
```

`prepare`は対象83社の全PREと候補corpus、較正値、候補結果、モデル/質問/共有writer/wrapperのソースSHAを固定する。今回のみ、停止前に取得済みの旧metaを任意の第4引数で再利用し、同じGETを再実行しなかった。`generate 83`は全検証に合格した先行5社の既存出力を再利用する。開始markerだけがあり終端出力のない会社は、未知結果として自動再実行しない。

本番適用は、全83出力がreviewableになり候補品質の判断とCIが揃った後に、運用者が明示して実行する別modeである。

```bash
pnpm exec tsx --env-file-if-exists=.env services/yuho-quant/data-scripts/recover-unjudged-competitors.ts apply <private-dir>
```

この調査・推論では`apply`を起動していない。適用直前に入力/物理archive/ソースSHA/schemaと旧値を再検査し、各PATCHの前にも全PRE一致を求める。競合4列以外を更新せず、固定83行以外へのPATCHはない。shared writerの`singleAttempt`指定はこの単発経路だけで使い、通常の既存呼出しを変更しない。送信markerのある行は自動再PATCHしない。対象外corpusの本文/タグ等が更新されていれば安全停止するため、その場合は旧判定へ新入力を黙って混ぜず、入力計画を作り直す。
