- 日次の保存経路はYahooの小数利回りを100倍して%へ変換していた。単位換算ではなく、取得元の値・報告期間・株数基準の整合が問題だった。

- 分割後の予想修正、増配、実績/予想の定義差が混在する。乖離だけからYahooと短信のどちらが正しいかは決めない。

## 予想利回りを採用するための未解決条件

1. 原本ごとの出典・利用条件を確認し、既存の公開数値契約である`commercial-ok`を満たすこと。内部財務行やTDnet由来というだけで公開資格を与えない。
2. 同一法人・対象期・連結範囲・年額/未定/無配を原本で確認し、株価と同じ株数基準にそろうこと。分割・併合・増資の法定効力と比率を表題や固定日数から推測しない。
3. 短信後の予想修正・訂正・取下げを正しい版へ反映し、必要原本を共有archiveで物理保管・SHA照合すること。
4. 未取込の短信XBRLと短信以外の配当予想修正を対象別に分類すること。旧調査の6871取込漏れや`no-forecast-row`は現在の未処理件数として再利用しない。
5. 上記を通常の機械処理・公開gate・保存前後照合へ接続し、対象を限定して受入れること。期間・主体・公開資格が不明な行はHOLDを維持する。
