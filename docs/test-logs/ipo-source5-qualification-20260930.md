# 新規上場3銘柄の一次資料照合

Refs #146。2026-09-30の観測。上場母集団とEDINETの提出者・業種を別の根拠として扱う。

## 実取得・保管

既存JPX上場一覧・EDINETコードリストを固定し、JPXが案内する企業の公式資料だけを5 GETで取得した。全応答HTTP200、各URL1回、再取得0。取得前に対象URL・既存JPX/FSA入力のSHA・送信予約を固定し、取得後に5応答の全bytesとSHAを保存した。

- [622Aの公告](https://www.tecraft.co.jp/ir/notice/)・[株式情報](https://www.tecraft.co.jp/ir/stock/)
- [627Aの公告](https://akippa.co.jp/ir/notice/)・[株式情報](https://akippa.co.jp/ir/stock/)
- [646Aの新規上場申請有価証券報告書Ⅰ](https://www.crasus.co.jp/content/files/IR/2026/20260929-Securitiesreport-1s.pdf)

共有 `notion-archive` で `ipo-bridge-20260930-daf8faeccd46` に物理保管。Notion API10回・hosted読取2回、ZIP 7,928,325 bytes、SHA256 `566321d0324dbf4fc45c7435c184dbb487ac47db2ad8ac89d5b2e4714107d91d`。全11メンバーの一意性・全長・SHAを照合した。公開Gitには原本全文を置かない。

## 仕組み側の対策と残件

PR #244で原本の基準日を取得日から分離し、マスタ・業種同期のCSV検証を共有した。PR #246で、月次一覧の欠損や上場区分差を上場廃止と推定する処理を撤去し、既存状態を保持して件数とコードを警告する。既存の正常値を消す原因への対策であり、上記3銘柄の欠損した識別根拠を補う修復とは区別する。

取得・保管後のD1業種更新、マスタ変更、通常stock-syncの手動起動は0。627Aの本番適用、622Aの区分差の解消、646Aの直接対応根拠の確認は未完。EDINET所有の業種をJPX値で上書きせず、既存Notionミラーの対応だけを出典証明として採用しない。
