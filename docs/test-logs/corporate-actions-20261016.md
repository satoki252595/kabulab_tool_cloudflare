Yahooの調整済み終値は分割・配当を反映する系列であり、通常終値と同じ系列ではない。[Yahoo公式説明](https://help.yahoo.com/kb/SLN28256.html)。この説明だけで全日本株のChart OHLC・出来高・配当額の株数単位や、増資等の全イベント処理を証明しない。増資を一律の分割比率で処理せず、利用可能な一次根拠と種類ごとの契約を#343へ結び付ける。

今回の修正は共有builderの入力検査と既存HOLD理由の追加だけで、追加取得・有料API・依存・DDL・ローカルでの価格再調整はない。通常値が揃った入力の計算は同じ。原典欠測時は従来の補完結果を更新せず、既存の失敗明細・原本batchへ残す。旧保存価格の一括補正は実施しない。

ローカル回復と本番は、ソース・lock・入力契約を共通にする。毎回両環境を全量比較する仕組みは追加せず、ローカル回復の対象だけ保存先で読戻し、定時は既存の全銘柄coverage・鮮度・完了receiptで検査する。

## 本番定時へ組み込む残件の受入条件

既存#343に結び付け、既存のYahoo取得原本・TDnet分類・JPX公開情報を使って決定的に処理する。LLMで日付・比率・調整係数を推定しない。追加の有料API・全銘柄への追加取得・保存価格の一括書換えは今回の監査では実施していない。

1. イベント種別ごとに、銘柄／株式種別、権利落日、基準日、法的効力日、株数基準、価格・出来高・1株配当額の調整状態、訂正versionを原本へ束縛する。開示タイトルの機械分類と、これらの値の確認を別の状態として保持する。
2. 計算ごとの実使用期間をイベントへ結び付ける。調整後終値と通常終値を比較する箇所も含め、基準一致が証明できた計算だけ公開する。既知の分割／併合が窓をまたぐ場合や基準不明のときは、当該計算を理由付きで保留し、受領価格に比率を二重適用しない。
3. 増資を分割と同じ係数で処理しない。発行方式・払込・権利内容を確認し、価格時系列の扱いと発行済株数／1株指標の更新を区別する。信用取引の数量・約定値段調整を現物株価の調整仕様へ転用しない。[JPXの権利処理説明](https://www.jpx.co.jp/equities/trading/margin/rights/02.html)、[JPX公表の対象銘柄](https://www.jpx.co.jp/markets/equities/rights/)（参照2026-10-16）。対象銘柄ページの現在表示だけで全日本株・全期間のcoverageを証明しない。
4. 正常な実原本と欠測・訂正・逆分割の負例を通常日次と保存原本replayの共通関数で検査し、本番の定時完了receiptと保存指標を確認してから対応済みとする。受入時には追加取得数・処理秒数・保存bytesを実測する。

## 終値トレンド・モメンタムの共通修正

通常の`sync:daily:core`と保存原本replayの共通builderで、終値SMAとの大小比較を受領adjcloseへ統一し、モメンタムも同じ応答のadjcloseで計算する。Yahooの調整値は分割・配当を反映する系列である。[Yahoo公式説明](https://in.help.yahoo.com/kb/adjusted-close-sln28256.html)（参照2026-10-16）。ローカルでイベント比率を再適用しない。

`p_momentum.closes`の消費者は`/financial-math/emh`の累積リターン・対数リターン分散計算で、約定価格には使っていない。画面の株価は`core_stock_financials.price`を別取得し、受領OHLCVのclose/open/high/low/volumeと日付・clockは保持する。既存の列追加禁止契約も維持する。配当反映前後でランキング値が変わりうるが、価格欠測を埋めて改善したとは扱わない。

実8303の保存済みprojectionで、通常取得とreplayの全snapshot・モメンタム列を照合。末尾90本が全て実adjcloseに一致し、通常終値列と異なること、累積リターン・ボラ計算との接続、元bytes/clockの保持を確認した。元原典の別日のadjcloseを末尾へ移した明示fault injectionでraw close/SMA比較の回帰を検出し、調整値の未設定・NULL・ゼロ・負・非有限はSTOPする。新規の取得元GET・モデル呼出し・依存・D1読取/書込・DDL追加は0。既存1銘柄1行の投影upsertへ相乗りし、同じ末尾90本のメモリ計算だけを変更する。

この修正はATR・前日比・出来高・OHLCの株数単位や、増資・新株予約権・会社分割等の統一契約を解決しない。該当計算の理由付きHOLDと日付・種類・株数単位を束縛する残件は#343に維持する。新ロジックの通常定時完了・本番保存結果の読戻しは別途必要で、CIやローカルreplayだけで本番受入済みにしない。

ローカル検証: Nix Node22.22.2/pnpm9.15.9でcron全24 suite/420 PASS、共有Yahoo/系列とEMH/テクニカルの追加5 suite/96 PASS、TypeScript・対象ESLint・diff check PASS。実8303の90本CSVは通常終値517Bから調整済み終値1,491Bへ増えた（+974B、精度を丸めない）。D1の行数とクエリ数は同じで、全銘柄の保存bytes差は次回実行で測る。同原本の新builderをウォームアップ後50,000回実行して164.934ms（約3.30µs/回、元サイト通信・モデル0）。これはローカルの純計算実測で、本番全体の時間・容量保証ではない。
