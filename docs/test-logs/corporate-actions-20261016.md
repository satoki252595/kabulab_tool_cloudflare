# 本番の権利イベント対応と価格系列の監査

確認: 2026-10-16。全体追跡[#348](https://github.com/satoki252595/kabulab_tool_cloudflare/issues/348)、価格・株数単位の一次証拠は既存[#343](https://github.com/satoki252595/kabulab_tool_cloudflare/issues/343)で追跡する。配当・分割の原値保存を完了した#272とは別の残件である。

| 対象 | 通常コードの現状 | 残る受入 |
|---|---|---|
| RSI・終値移動平均・MACD | 日次と保存原本replayが同じbuilderを使用。今回、調整済み終値の欠測を通常終値で補完する経路を除去 | 次回の通常日次、実原本と保存指標の確認。修正のCIを定時成功とは数えない |
| 調整値の欠測 | 直近130本に通常終値だけがある日は計算前にSTOP。古い5年範囲だけなら原SHA・件数・期間とmissing_adjusted_closeを記録し、既存RSIを保持 | 欠測を「分割なし」と解釈しない。終値・調整値ともNULLの日は欠測を維持 |
| 配当・分割／併合イベント | Yahooの原timestamp、分子・分母・比率、配当額・通貨、対応価格SHA、訂正履歴を保存。支払日はnot-provided | 取得応答のイベントを全期間の完全な権利台帳とは扱わない |
| VWAP・5分足 | quote受領値のbasisを明示。日足原本の観測期間で分割なしを確認できる窓だけを認定 | 分割をまたぐ窓やprovider側の価格・出来高の株数単位が不明なものはHOLD。係数を推測で再適用しない |
| 増資・新株予約権・会社分割等 | TDnetの開示取得・分類は存在 | 正式な種類・効力日・権利落日・株数単位・価格basisを結び付ける統一処理は未完。単なる開示分類を計算対応済みとしない |

Yahooの調整済み終値は分割・配当を反映する系列であり、通常終値と同じ系列ではない。[Yahoo公式説明](https://help.yahoo.com/kb/SLN28256.html)。この説明だけで全日本株のChart OHLC・出来高・配当額の株数単位や、増資等の全イベント処理を証明しない。増資を一律の分割比率で処理せず、利用可能な一次根拠と種類ごとの契約を#343へ結び付ける。

今回の修正は共有builderの入力検査と既存HOLD理由の追加だけで、追加取得・有料API・依存・DDL・ローカルでの価格再調整はない。通常値が揃った入力の計算は同じ。原典欠測時は従来の補完結果を更新せず、既存の失敗明細・原本batchへ残す。旧保存価格の一括補正は実施しない。

ローカル回復と本番は、ソース・lock・入力契約を共通にする。毎回両環境を全量比較する仕組みは追加せず、ローカル回復の対象だけ保存先で読戻し、定時は既存の全銘柄coverage・鮮度・完了receiptで検査する。

検証: Nix Node22.22.2/pnpm9.15.9、関連5 suite/133 PASS、TypeScript・対象ESLint・diff check PASS。保存済み実8303/7203 projectionを使用し、明示的に調整値をNULLにした負例で過去RSIのHOLD、直近計算STOP、通常終値への非置換を確認。正常入力・8303既存の非正調整値HOLD・全列保存と時計保持を回帰確認し、相場API追加GETは0。
