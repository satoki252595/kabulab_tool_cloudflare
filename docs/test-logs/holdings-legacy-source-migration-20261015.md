# 保有明細の通常旧行移行（2026-10-15）

通常取込・保存原本backfill・再開queueが共用する `publishHoldings` を修正。旧行の保有種別が未記録だと従来の自然キー検索から外れ、原表と対応可能でも新規行を作っていた。提出会社と期末のwindowを一度読み、原表全体の同名行も含めた一対一対応を確認する。

旧行の提出会社コード・主体名・銘柄名・期末が完全一致し、種別欠測、照合フラグfalse、出典未記録の唯一行だけが移行候補。同名複数種別、重複、別主体、既照合flag、矛盾した出典は文書単位でHOLD。別名推定や未開示の推定はしない。通常の既存キーも保持し、書込前はfresh全props/clockを再検査する。

移行windowは既存の未確定markerにPREのキー/SHAを記録し、旧行の全propsを物理保管・全文読戻しした後に単発PATCHする。旧専用列と無関係な列を保持し、canonical値の原表による置換を明記。別GETで独立POSTを取り物理保管するまでcursorを進めない。PRE・PATCH・POST結果不明は自動再送しない。完了markerがある文書も全原表のfile/context/raw行/SHAを照合し、価格資格は別扱いとする。

Nix Node 22.22.2 / pnpm 9.15.9・既存lockで関連3 suiteは109 PASS、型検査・対象lintも通過。実在する固定cutoffの27,594旧行と22,755原表明細の全SHA replayでは、12,709旧行がfresh PRE候補、7,287行が既存キーなし、89文書/2,746明細がHOLD、13行が全通常出典一致だった。3実ZIPも再解析済み。これは現在の本番書込や全行の価格資格を認定する結果ではない。

依存追加・LLM・新しい外部原本取得は0。DB全表を行ごとに検索せず、提出会社/期末の候補読取は上限1,000行、取込は既存最大100行/runを維持する。既存行のfresh GET、移行行の独立POST GET、移行windowごとのPRE/POST各1ファイル保管は増える。旧行へ対応できる分の新規明細作成を避ける。追加保管・読戻しの本番所要は未測定であり、回復は件数と通信予算を固定して段階実行する。

私有原本・旧props・URLはGit対象外。独立replayは `holdings-normal-legacy-root-review-v1/SUCCESS.json`。本番適用時は固定cutoffを現況と読み替えず、最新文書と候補windowを再取得して資格化する。
