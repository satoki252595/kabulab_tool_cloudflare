# 純利益ROAの直接開示値の取込

通常の `edinet_daily` / `tdnet_hourly` が呼ぶ `tidy_to_financial_record` は、ROAを常に未取得にしていた。利益と総資産からの計算は行わず、有報の直接開示された当期実績文だけを既存 `FinancialSummaryRecord.roa_pct` へ渡す。

## 取込契約

- 既存の type5/type1 → tidy → normalize → `ctx.persist` → Notion③ `ROA%`、`ctx.cloud_financial_summary` → D1 `jss_financials.roa_pct` を使用する。列・バケット・依存は追加しない。
- `TypeOfCurrentPeriodDEI=FY`、`CurrentPeriodEndDateDEI`、連結作成DEI、レコードの連結区分が一致する必要がある。提出日時点のMDA本文を当期末の数値ファクト用フィルタで捨てない。
- 純利益を分子とする総資産利益率の明示定義、当年度、全社主体、百分率、実績完了文を照合する。「前期から当期へ」の文章では後者だけを採る。
- 目標・予想・3年平均・前年値・セグメント・多値・不完全文を採らない。経常/営業/事業/税引前ROAや退職給付信託の円建て値はROAへ代入しない。裸ROAの日本語修飾も検査し、別定義へ前段の純利益定義を引き継がない。
- HTMLは既存lxmlでタグ境界を空白として保つ。数値を隣のセルと連結せず、表の列や欠けた境界を推測しない。
- 未対応/不明は `None` を維持する。全社に数値が埋まったとは扱わない。

## 保存原本での受入

最新3666通（解消済み19通を含む）の原本・資格manifest・native提出者/期末を全SHA照合した。407,341,177B・5,621,615行。空の項目名や拡張要素名を含む指定検索範囲で、純粋な比率単位かつ数値を持つ専用ROA候補は0だった。すべての将来/独自タグが存在しないという主張ではない。
